# Native workbench validation — November 11, 2026

Created by Jason Stys. This report separates observed local source/package checks
from later hosted validation, public release and PC installation.

## Change and practical behavior

The graphical workbench invokes the original dependency-free Rust wire decoder,
full-snapshot Python detectors, parameterized SQLite search and snapshot-bound
query core. An analyst selects permitted captures/logs and thresholds, reviews
findings and capture gaps, changes exact time/protocol/rule/severity filters, pages
saved normalized evidence and exports the actual retained bundle. The original
CLI retains its explicit input/output paths. There is no live traffic interface.

Six in-app prepared input scenarios cover DNS response bursts plus distinct log
events, benign office lookup, industrial telemetry, TCP port fan-out, truncated
captures and an actual higher DNS threshold. Prepared files are generated by the
original authored synthetic generator inside the selected private profile. An
edited prepared file is refused rather than overwritten. A seventh native
workflow uses the real next-page button on an earlier saved snapshot; an eighth
uses the actual file chooser with external normalized logs. Policies and original
inputs are hashed, while the policy hash is explicitly a normalized-content hash.

The GUI's owner-local history is bounded and transactionally retains completed
outputs. Failed input, stale cursor/filter, full history and export collisions
cannot silently replace prior evidence. Exit retains the profile lock while the
finite worker finishes. All file input now uses a nonblocking regular one-link
descriptor with identity/size/timestamp checks, including the original CLI reader.
The decoder receives only minimal OS runtime/temporary environment variables.

## Test findings and correction

The first frozen attempt completed the six original scenario workflows and saved
the seventh page, then failed a newly authored acceptance assertion: its expected
packet labels were incorrectly written as `pcap:3`/`pcap:4`. The original decoder
contract uses `packet-N`; with the equal-time independent log entry, the correct
second page is `packet-2` at 1,000,000,000 ns and `packet-3` at 2,000,000,000 ns.
The failure receipt, original package metadata and executable checksum were
preserved privately. No immutable old EXE copy was retained. The source unit
oracle now independently checks those exact identifiers and times. The same full
frozen journey passed after the assertion correction; no budget, sample, core
result or original gate was changed to make it pass.

The initial combined coverage observation was 94.94%, below the retained floor.
Meaningful next-page, edited-input, descriptor, child-environment and resource
boundary tests increased actual exercised behavior. The floor was not reduced.

## Scope and delivery status

Local working-tree package receipts explicitly report `source_dirty=true` until
the reviewed source is committed; a clean-source rebuild and exact-head hosted
results are separate delivery evidence. The added Windows CI lane builds and
uses the actual EXE without artifact/cache uploads, alongside all original gates.
This document does not claim an unobserved future CI, public release or install.
Root delivery records retain their own exact source and package identities.

This remains offline educational analysis of authorized supplied data, not an IDS,
host scan, authenticated evidence-acquisition service, network safety proof,
malware certificate, source attribution or automatic enforcement system. Capture
issues are deliberately unfiltered; detector references can be capped while total
counts remain explicit. Local plaintext is not protection against the OS owner or
administrator. Original historical reports and Office editions keep their own
tested revision and date.
